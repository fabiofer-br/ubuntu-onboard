# Microsoft SQL Server 2022 for Linux (Docker)

## Download, Start, and Operation 

The official production-ready image provided directly by Microsoft is hosted on the **Microsoft Container Registry (MCR)**.

The primary identifier for SQL Server 2022 on Linux is:
`[mcr.microsoft.com/mssql/server:2022-latest](https://mcr.microsoft.com/mssql/server:2022-latest)`

By default, launching this image without passing a specific product ID initiates the **Developer Edition**, which is completely free for development, learning, and testing environments and includes all the features of the Enterprise edition.

---

### The Quick Start Command

To spin up a container instantly on your local Ubuntu development workstation, open your terminal and run the following `docker run` command:

```bash
docker run -e "ACCEPT_EULA=Y" \
           -e "MSSQL_SA_PASSWORD=YourStrong@Password123" \
           -p 1433:1433 \
           --name mssql2022 \
           -d mcr.microsoft.com/mssql/server:2022-latest

```

---

### Key Flags Breakdown

* **`-e "ACCEPT_EULA=Y"`**: Required. Confirms your acceptance of the End-User License Agreement.
* **`-e "MSSQL_SA_PASSWORD=..."`**: Required. Sets the system administrator (`sa`) password. It **must** comply with SQL Server’s default password complexity policy (at least 8 characters, containing uppercase, lowercase, base-10 digits, and/or symbols), otherwise the container will abruptly shut down right after initialization.
* **`-p 1433:1433`**: Binds the container's default SQL Server port (`1433`) directly to port `1433` on your local machine.
* **`-d`**: Runs the container detached in the background.

**Useful Commands**

```bash
docker container ps --all
docker stop mssql2022
docker start mssql2022
docker image ls -all
docker info
```

### Verifying and Connecting locally

Once the container is running, you can connect directly to it from your development workstation using various tools:

#### 1. Via VS Code (The Cleanest Workflow)

Since you have your native `.deb` VS Code environment set up, you can connect straight from your editor:

1. Install the official **mssql** extension in VS Code.
2. Click the **SQL Server** icon on the sidebar activity bar.
3. Click **Add Connection** (`+`) and use the following parameters:
* **Server name**: `localhost`
* **Database name**: (Leave blank for default/master)
* **Authentication Type**: `SQL Server Authentication`
* **User name**: `sa`
* **Password**: The strong password you defined in your `docker run` command.



#### 2. Using Command-line Tools inside the Container

Microsoft includes the CLI tools (`sqlcmd`) right inside the image. You can attach to the container to run inline queries:

```bash
docker exec -it mssql2022 /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "YourStrong@Password123" -C

```

*(Note: The `-C` flag forces `sqlcmd` to trust the server's implicit certificate, which is usually required by default in modern image updates).*

## Data Persistence for Docker SQL

If you stop or remove the container, any databases you create inside it will vanish. For active project development, bind a local directory (such as a directory inside your user profile) to the container's storage folder using a volume mount flag:

```bash
-v ~/my_sql_data:/var/opt/mssql

```
When you run a Docker container, it creates its own isolated, temporary file system. By default, any databases you create, tables you populate, or logs generated by SQL Server are written inside that temporary container layer.

If you stop the container (docker stop mssql2022) and start it again, your data is safe. However, if you **remove** the container (docker rm mssql2022) to update the image version, fix a configuration, or clear up resources, **that temporary file system is completely destroyed, and your data vanishes forever.**

To prevent this, you use **Volumes** or **Bind Mounts**. This maps a standard folder on your real Ubuntu machine directly into the container's internal SQL Server data directory.

---

### The Persistence Directory

Inside the Linux SQL Server container, all databases and system configurations are stored in the internal path: /var/opt/mssql.

Your goal is to point that internal path to a safe, permanent folder on your development workstation.

### Step-by-Step Setup

#### 1. Create a safe folder on your host machine

First, create a dedicated folder in your home directory where your databases will physically live.

```bash
mkdir -p ~/projects/sql_data
```

#### 2. ⚠️ The Ubuntu Permissions Gotcha (Crucial)

Because SQL Server inside the container runs under a specific non-root user ID (uid=10001), the container needs permission to read and write to the folder you created on your Ubuntu host.

If your container suddenly stops right after launching and the logs (docker logs mssql2022) complain about access denied or permission errors, you just need to grant ownership of that local folder to the SQL Server user id:

```bash
sudo chown -R 10001:0 ~/projects/sql_data
```

This ensures the containerized SQL instance has absolute full rights to write your database files to your local drive.

#### 3. Run the container with the -v flag

When you launch the container, you use the -v (volume) flag using the format: -v /host/path:/container/path.

```bash
docker run -e "ACCEPT_EULA=Y" \
           -e "MSSQL_SA_PASSWORD=YourStrong@Password123" \
           -p 1433:1433 \
           --name mssql2022 \
           -v ~/projects/sql_data:/var/opt/mssql \
           -d mcr.microsoft.com/mssql/server:2022-latest
```

---

### Why this is a game changer for development

Once you include that -v ~/projects/sql_data:/var/opt/mssql line, the dynamic changes completely:

* **Immunity to Deletion:** You can run docker rm -f mssql2022 at any time. Your actual database .mdf and .ldf files remain safe in your ~/projects/sql_data folder.
* **Instant Upgrades:** When Microsoft releases a newer cumulative update for SQL Server 2022, you can pull the new image, delete the old container, spin up a new one using the exact same -v command, and your database will be right there, fully attached and upgraded automatically.
* **Easy Backups:** Want to make a backup copy of your entire development database environment before testing a massive schema migration? Just compress or copy your local ~/projects/sql_data folder.
